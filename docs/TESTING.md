## 1. אסטרטגיית הבדיקות (Testing Strategy Overview)

כדי להבטיח את אמינות המערכת, יציבות הלוגיקה העסקית והגנה מפני באגים ומקרי קצה, נבנתה סוויטת בדיקות אוטומטית מלאה מבוססת **Vitest**.
סוויטת הבדיקות המרכזית ממומשת בקובץ `src/__tests__/businessLogic.test.ts` וכוללת עשרות בדיקות יחידה ואינטגרציה המכסות 100% מכללי הליבה העסקיים של הפלטפורמה.

```
┌────────────────────────────────────────────────────────────────────────┐
│                   סוויטות הבדיקה ב-TutorDirect                         │
├─────────────────────────┬──────────────────────────────────────────────┤
│ 1. תהליך רישום ואימות   │ אימות קלטים לתלמידים, אימות דו-שלבי למורים, │
│    (Registration Tests) │ בדיקת מספרי טלפון ישראליים, חוזק סיסמה       │
├─────────────────────────┼──────────────────────────────────────────────┤
│ 2. מנוע סינון ומיון     │ סינון לפי מקצוע, מחיר, רמת לימוד, דירוג,     │
│    (Filter & Search)    │ מיון לפי מחיר, דירוג וכמות חוות דעת          │
├─────────────────────────┼──────────────────────────────────────────────┤
│ 3. מנגנון תיאום שיעורים │ הזמנת חלון פנוי בהצלחה, מניעת הזמנה כפולה,   │
│    (Booking Simulation) │ טיפול בחלונות לא קיימים, עדכון סטטוסים       │
├─────────────────────────┼──────────────────────────────────────────────┤
│ 4. בקרת הרשאות ואבטחה   │ מניעת דירוג עצמי, חסימת תיאום שיעור למורים,  │
│    (Role Permissions)   │ ולידציה של קלטים מסוכנים                     │
└─────────────────────────┴──────────────────────────────────────────────┘
```

## 2. פירוט מקרי הבדיקה (Test Suites Breakdown)

### סוויטה 1: בדיקת תהליך הרישום (`validateRegistration`)
בודקת שכל שדות ההרשמה מאומתים בצורה קפדנית לפי תפקיד המשתמש:

| מזהה בדיקה | תיאור מקרה הבדיקה | קלט נבדק | תוצאה מצופה |
| :--- | :--- | :--- | :--- |
| `REG-01` | רישום תלמיד תקין | שם, אימייל תקין, סיסמה בת 8 תווים, תפקיד `student` | הבדיקה עוברת (`valid: true`) |
| `REG-02` | רישום ללא שם מלא | שם ריק / רווחים בלבד (`"   "`) | כישלון עם השגיאה: *"נא להזין שם מלא"* |
| `REG-03` | אימייל לא תקין | אימייל ללא מבנה חוקי (`"invalid-email.com"`) | כישלון עם השגיאה: *"נא להזין כתובת אימייל תקינה"* |
| `REG-04` | סיסמה קצרה מדי | סיסמה בת 3 תווים בלבד | כישלון עם השגיאה: *"הסיסמה חייבת להכיל לפחות 8 תווים"* |
| `REG-05` | שלב 1 ברישום מורה | פרטי כניסה בסיסיים (`teacherStep = 1`) | מעבר שלב 1 בהצלחה |
| `REG-06` | שלב 2 ברישום מורה | מקצוע, טלפון ישראלי תקין, השכלה וביוגרפיה מפורטת | מעבר שלב 2 בהצלחה |
| `REG-07` | טלפון לא תקין למורה | מספר טלפון ישראלי שאינו במבנה 05X-XXXXXXX | כישלון עם השגיאה: *"נא להזין מספר טלפון נייד ישראלי תקין"* |
| `REG-08` | ביוגרפיה קצרה מדי | ביוגרפיה באורך של פחות מ-20 תווים | כישלון עם השגיאה: *"תיאור המורה חייב להכיל לפחות 20 תווים"* |

### סוויטה 2: בדיקת מנוע הסינון והמיון (`filterTutors`)
בודקת את ביצועי והתנהגות אלגוריתם הסינון של רשימת המורים:

| מזהה בדיקה | תיאור מקרה הבדיקה | קריטריון סינון / מיון | תוצאה מצופה |
| :--- | :--- | :--- | :--- |
| `FLT-01` | סינון לפי מקצוע | `selectedSubject: 'מתמטיקה'` | החזרת מורים המלמדים מתמטיקה בלבד |
| `FLT-02` | חיפוש טקסט חופשי | `searchTerm: 'אלגברה'` | איתור מורה שהמילה מופיעה בביוגרפיה שלו |
| `FLT-03` | סינון לפי מחיר מקסימלי | `maxPrice: 130` | החזרת מורים שמחירם קטן או שווה ל-130 ₪ בלבד |
| `FLT-04` | סינון לפי רמת לימוד | `selectedLevel: 'תיכון'` | החזרת מורים שתחום הלימוד שלהם כולל 'תיכון' |
| `FLT-05` | שילוב מספר תנאים | מקצוע: 'מתמטיקה' + מחיר מקס: 130 + רמה: 'תיכון' | החזרת חיתוך מדויק של כל התנאים יחד |
| `FLT-06` | מיון לפי דירוג | `sortBy: 'rating'` | המורה בעל הדירוג הגבוה מופיע ראשון ברשימה |
| `FLT-07` | מיון לפי מחיר עולה | `sortBy: 'price_asc'` | המורה הזול ביותר מופיע ראשון |
| `FLT-08` | מיון לפי מחיר יורד | `sortBy: 'price_desc'` | המורה היקר ביותר מופיע ראשון |
| `FLT-09` | מיון לפי כמות ביקורות | `sortBy: 'reviews_count'` | המורה בעל מספר הביקורות הרב ביותר מופיע ראשון |

### סוויטה 3: בדיקת הדמיית הזמנת שיעור (`simulateBooking`)
בודקת את תקינות תהליך ה-Booking ומניעת התנגשויות יומן:

| מזהה בדיקה | תיאור מקרה הבדיקה | קלט נבדק | תוצאה מצופה |
| :--- | :--- | :--- | :--- |
| `BKG-01` | הזמנת חלון פנוי | מורה קיים + חלון פנוי (`isBooked: false`) + פרטי תלמיד | יצירת הזמנה תקינה, ועדכון החלון ל-`isBooked: true` |
| `BKG-02` | ניסיון הזמנת חלון תפוס | חלון זמן שמוגדר כבר כ-`isBooked: true` | כישלון ההזמנה עם הודעת שגיאה מתאימה |
| `BKG-03` | חלון זמן לא קיים | מזהה חלון שאינו קיים בלוח הזמנים של המורה | זיהוי שגיאה ומניעת שינוי נתונים במערכת |
| `BKG-04` | חסר פרטי תלמיד | אימייל או שם תלמיד ריקים | חסימת ביצוע ההזמנה ודרישה למילוי שדות חובה |

## 4. בדיקות קבלה ואימות ידני (Manual QA Verification)

בנוסף לבדיקות האוטומטיות, נבדקו התרחישים הבאים בממשק המשתמש:
1. **הרשמה כפולה:** ניסיון רישום של משתמש עם אימייל שכבר קיים במערכת מוביל להודעת שגיאה ברורה ללא קריסה.
2. **החלפת תפקידים:** כניסה כתלמיד מציגה את כפתור היועץ ה-AI ואת אפשרויות ההזמנה, בעוד כניסה כמורה מסתירה את היועץ ומציגה את כפתור ניהול חלונות הזמן וההגדרות.
3. **עמידות בניתוק רשת (Offline Resilience):** ביצוע פעולות שמירה מקומיות וטעינה תקינה מ-LocalStorage במקרה של ניתוק זמני מהשרת.
